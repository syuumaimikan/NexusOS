NexusOS

A desktop operating system written from nothing, in Rust.

Not a Linux distribution and not a BSD fork. The bootloader, the kernel, the filesystem, the TCP stack, the compositor, the font rasteriser, the PNG and JPEG decoders and every program on the desktop were written for this system. There is no libc, no std, and no floating point in the kernel.

The idea it is built on

Nothing is ambient. A program starts holding one channel and nothing else. Every other power it has arrived in a message: a directory handle, a channel to a service, a page of shared memory. There is no path from a program to a file it was not lent, no way to start a program except by asking something that holds the authority to, and no global namespace to look anything up in.

Handles carry rights — READ, WRITE, TRANSFER, CLOSE. TRANSFER is the right to cross a channel at all. A handle lent without CLOSE cannot be taken away from the lender, and duplicate may only narrow rights, never widen them.

This is not aspirational. The agent window is lent one directory with read and transfer, and the first thing it does is try to create a file there and report being refused. A program that merely does not write is not a program that cannot.

What is honestly not here

This table is the part of the documentation worth reading first. Everything the system cannot do is named, with the reason, rather than left to be discovered.

Not hereWhy
HTTPS TLS needs a cipher suite, a key exchange, certificate parsing and a chain of trust. The browser fetches http:// only, and says so.
Threads in a process One thread per process. Anything wanting concurrency inside a program is an event loop, because there is no second thread to give it.
Standard output, pipes, fork None of them. A program is given channels, not file descriptors. It is why ls is built into the terminal rather than being a program.
A battery reading ACPI's fixed registers give shutdown and reset, and both work. The battery is an AML method, and running AML means writing an interpreter. See power.
Suspend to RAM S3 means saving processor state and reinitialising every device on the way back. Getting it wrong is a machine that does not come back.
Loadable drivers No module loader, no driver ABI, no way to revoke one. Doing it badly is worse than not doing it.
Windows software A PE loader is a fortnight. The Win32 subsystem behind it is what Wine has been writing since 1993.
A compiler on the machine Writing software for NexusOS works today, from another machine. Writing it on NexusOS needs an editor, an assembler and a linker that run here.

The full list, with sizes and reasons, is in the roadmap.

The rules it is written under

  • Build after writing code. Never leave the tree broken.
  • No todo!(), no unimplemented!(), no mock layer. If a thing is not implemented, it is absent and the roadmap says so.
  • unsafe is allowed and carries a // SAFETY: comment saying why it holds.
  • Nothing is "verified" because it compiled. It is verified because it ran.
  • Never ignore a warning.
  • Every user-visible string lives in locales/, in both languages, or the build fails.

Running it

powershell -File scripts/build.ps1   # kernel, bootloader, programs, disk image
powershell -File scripts/run.ps1     # boot it in QEMU
powershell -File scripts/test.ps1    # the whole suite

The suite is nineteen stages. The first four run on the build machine and take seconds; the rest boot a real machine under QEMU and read its serial log. Among them: a boot from the disk image alone, so the firmware reads the partition table and filesystem this project writes; a persistence test that boots twice and requires the second boot to find what the first one wrote; an input test that sends real keystrokes through the same 8042 controller; and six fault-injection builds that break the kernel one way each and require every one to be reported rather than resetting the machine.

Which crates get linted and tested is not a list somebody maintains — it is checked against cargo metadata, and a crate that is on no list fails the suite by name. That check exists because the list had gone short: the bootloader's entry point, the first code that runs on the machine, had never been linted at all.
