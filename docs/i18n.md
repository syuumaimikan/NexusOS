# Localisation / 国際化

NexusOS ships in **English and Japanese**, and the language can be changed while
the system is running.

NexusOS は **英語と日本語**に対応しています。言語は実行中に切り替えられます。

---

## Adding or editing a language / 言語の追加・編集

Everything a person reads lives in `locales/`, one file per language, named by
its BCP 47 tag:

画面に表示される文字列はすべて `locales/` にあります。1 言語 1 ファイルで、
ファイル名は BCP 47 タグです。

```
locales/en-US.txt
locales/ja-JP.txt
```

The format is `key = value`, one per line, UTF-8, with `#` for comments:

書式は 1 行 1 組の `key = value`、UTF-8、`#` はコメントです。

```
status.memory = memory
value.memory = {free} MiB free of {total} MiB
```

```
status.memory = メモリ
value.memory = 全 {total} MiB 中 {free} MiB 空き
```

Adding a language means adding a file. No kernel source changes.

言語を追加する作業は、ファイルを 1 つ足すことだけです。カーネルのソースを
変更する必要はありません。

## Why placeholders are named / プレースホルダに名前がある理由

Look at the two `value.memory` lines above. English puts the free figure first;
Japanese puts the total first. A positional format string (`{0} of {1}`) cannot
express that difference without the translator getting the order wrong, and the
mistake would be silent. Named placeholders let each translation order its
arguments however that language wants.

上の `value.memory` を見てください。英語は空き容量を先に、日本語は総容量を先に
置いています。位置指定の書式文字列 (`{0} of {1}`) ではこの違いを表現できず、
翻訳者が順序を誤っても気づけません。名前付きなら、各言語が自然な語順を選べます。

## A missing translation is a build error / 未翻訳はビルドエラー

`build.rs` compares the keys in every locale file. If one language defines a key
another does not, the build fails and names the key. The alternative — a label
that silently renders blank, or quietly falls back to English — is a defect that
ships.

`build.rs` は全ロケールファイルのキーを比較します。ある言語にだけキーがない
場合、ビルドは失敗し、そのキー名を表示します。放置すると、ラベルが黙って空欄に
なるか英語に戻る不具合がそのまま出荷されてしまいます。

## Serial logs stay in English / シリアルログは英語のまま

Log output is a developer interface. It has to stay greppable across machines,
and a bug report is far more useful when its log reads the same everywhere, so
nothing on the serial line is translated — and nothing on it is non-ASCII
either, because UTF-8 in a terminal set to another encoding is just mojibake.
Language changes are logged by tag (`ja-JP`), not by name.

ログは開発者向けのインターフェースです。どの環境でも grep でき、不具合報告の
ログが同じ文面である方が役に立つため、シリアル出力は翻訳しません。ASCII 以外も
出しません。別の文字コードに設定された端末では UTF-8 は文字化けするだけだから
です。言語の切り替えはタグ (`ja-JP`) で記録します。

## Fonts / フォント

The kernel has no font file and no rasteriser. Hand-authoring a CJK face is not
realistic — the kana alone would be hundreds of bitmaps — and committing a
system font's bitmaps to this repository would be redistributing that font,
which its licence generally does not permit.

カーネルはフォントファイルもラスタライザも持ちません。CJK の字形を手作業で
起こすのは現実的ではなく（かなだけでも数百字あります）、システムフォントの
ビットマップをこのリポジトリに含めることは再配布にあたり、多くの場合ライセンス
が許しません。

So `scripts/generate-font.ps1` rasterises, at build time, exactly the characters
the locale files use, from a font already installed on the machine doing the
build. The result goes to `target/` and is never committed. Each build machine
uses its own licensed copy — the same arrangement as linking against a system
library.

そのため `scripts/generate-font.ps1` が、ビルド時に、ロケールファイルで実際に
使われている文字だけを、ビルドマシンに導入済みのフォントからラスタライズします。
結果は `target/` に出力され、コミットされません。各ビルドマシンが自分のライセンス
下のフォントを使う形で、システムライブラリにリンクするのと同じ考え方です。

If rasterisation cannot run, the build still succeeds. The kernel falls back to
its built-in ASCII face, non-Latin text renders as placeholder boxes, and the
boot log says so plainly rather than leaving the cause to guesswork:

ラスタライズできない場合でもビルドは成功します。カーネルは内蔵の ASCII 字形に
フォールバックし、非ラテン文字は代替の枠として描画され、起動ログがその旨を
はっきり伝えます。原因の推測は不要です。

```
[disp] no generated glyphs; falling back to the built-in ASCII face
```

### Choosing a font / フォントの選択

By default the script takes the first installed font from a preference list
headed by MS Gothic, which carries hand-tuned bitmaps at small sizes. Override
it with `-FontName`.

既定では MS Gothic を先頭とする候補リストから、導入済みの最初のフォントを使い
ます。MS Gothic は小さいサイズ用に調整されたビットマップを持っています。
`-FontName` で変更できます。

The em size is not assumed; it is chosen by rasterising the widest characters of
each class and taking the largest size whose ink actually fits the 16-pixel cell.
Asking MS Gothic for a 16-pixel em produced glyphs nine pixels wide against an
eight-pixel half-width cell, which clipped the right-hand stem off every `N` and
`O` and rendered the title as "NexusCS". Measuring the drawing, rather than
trusting the font metrics, is what fixed it.

em サイズは決め打ちしません。各クラスで最も幅の広い文字を実際にラスタライズし、
インクが 16 ピクセルのセルに収まる最大サイズを選びます。MS Gothic に 16 ピクセル
の em を要求すると 9 ピクセル幅の字形が返り、8 ピクセルの半角セルからはみ出して
`N` と `O` の右の縦線が切れ、タイトルが「NexusCS」と表示されました。フォントの
メトリクスを信じるのではなく描画結果を測ることで解決しました。

## Layout is measured in pixels / レイアウトはピクセルで測る

A Japanese label is full-width and an English one half-width, so the same
character count is a different number of pixels. The status panel measures its
text and sizes itself to fit, in both directions, dropping the text scale when
it has to. Sizing by character count would draw Japanese values outside the
rectangle the next refresh clears, and consecutive frames would overlap into
unreadable text.

日本語のラベルは全角、英語は半角なので、同じ文字数でもピクセル数は異なります。
ステータスパネルは文字列を実測し、縦横ともに収まるよう自分の大きさを決め、必要
なら文字の拡大率を下げます。文字数で大きさを決めると、日本語の値が次の再描画で
消去される矩形の外側に描かれ、フレームが重なって判読できなくなります。

## What is not done yet / 未対応

* **No input method.** There is no keyboard driver, so there is nothing to type
  into and no IME. / キーボードドライバがないため、入力手段も IME もありません。
* **No vertical text**, no bidirectional text, no complex shaping. Each glyph is
  drawn on a fixed grid. / 縦書き、双方向テキスト、複雑な字形処理には未対応です。
  字形は固定グリッドに描画されます。
* **The language cycles on a timer.** There is no settings UI to choose it from,
  and a language selectable only at build time has not really been shown to work,
  so a thread alternates between them to demonstrate that every string and the
  layout around it are recomputed live. This goes away when settings exist. /
  設定画面がなく、ビルド時にしか選べない言語では「動作する」と言えないため、
  スレッドが言語を交互に切り替え、文字列とレイアウトが実行時に再計算されること
  を示しています。設定機能ができ次第、この挙動はなくなります。
* **Only two languages.** Chinese and Korean need no new code, only files — but
  they would widen the glyph set considerably, so they wait until there is a
  reason. / 中国語と韓国語はコード変更なしにファイルだけで追加できますが、字形が
  大幅に増えるため、必要になるまで見送ります。
